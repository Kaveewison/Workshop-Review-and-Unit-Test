# Lab 00 ข้อ 5 — Test cases ของระบบเลือกตั้งส่วนที่รับผิดชอบ

**ส่วนที่รับผิดชอบ:** การเพิ่มผู้สมัครรับเลือกตั้ง (`ElectionService.addCandidate`) ใน Election App ที่ทำในวิชา Backend

**กฎของระบบ (อ่านจากโค้ด):**

1. ต้องส่ง `candidateNumber`, `partyId`, `constituencyId`, `userId` มาครบ
2. ผู้ใช้ต้องมีอยู่จริง และต้องอาศัยอยู่ในเขตที่จะลงสมัคร
3. ผู้ใช้ 1 คนเป็นผู้สมัครได้แค่ครั้งเดียว
4. พรรคและเขตเลือกตั้งต้องมีอยู่จริง
5. หมายเลขผู้สมัครห้ามซ้ำกันในเขตเดียวกัน
6. นโยบาย (`policy`) ไม่บังคับ ถ้าไม่ส่งมาให้บันทึกเป็นค่าว่าง (`null`)

| ID | Given | When | Then |
|---|---|---|---|
| TC-01 | ผู้ใช้ A อาศัยอยู่เขต 1, มีพรรค P และเขต 1 อยู่จริง, หมายเลข 1 ในเขต 1 ยังไม่มีใครใช้ | admin เพิ่ม A เป็นผู้สมัครหมายเลข 1 ของพรรค P ในเขต 1 พร้อมนโยบาย | ระบบบันทึกผู้สมัคร ผูกกับ A, P และเขต 1 พร้อมนโยบายที่ส่งมา |
| TC-02 | เหมือน TC-01 | admin เพิ่ม A โดยไม่ส่งนโยบาย | ระบบบันทึกผู้สมัคร และนโยบายเป็นค่าว่าง (`null`) |
| TC-03 | ผู้ใช้ A อาศัยอยู่เขต 2 | admin เพิ่ม A เป็นผู้สมัครในเขต 1 | ระบบปฏิเสธ แจ้งว่าผู้ใช้ไม่ได้อาศัยอยู่ในเขตนี้ และไม่บันทึกอะไรลงฐานข้อมูล |
| TC-04 | ผู้ใช้ A เป็นผู้สมัครอยู่แล้ว | admin เพิ่ม A เป็นผู้สมัครอีกครั้ง | ระบบปฏิเสธ แจ้งว่าผู้ใช้นี้เป็นผู้สมัครอยู่แล้ว |
| TC-05 | ผู้สมัครอีกคนใช้หมายเลข 1 ในเขต 1 ไปแล้ว | admin เพิ่ม A เป็นหมายเลข 1 ในเขต 1 | ระบบปฏิเสธ แจ้งว่าหมายเลข 1 ถูกใช้ในเขตนี้แล้ว |
| TC-06 | ผู้สมัครอีกคนใช้หมายเลข 1 ใน**เขต 2** | admin เพิ่ม A เป็นหมายเลข 1 ใน**เขต 1** | ระบบบันทึกได้ เพราะหมายเลขห้ามซ้ำแค่ในเขตเดียวกัน |
| TC-07 | ไม่มีพรรค ID 99 ในระบบ | admin เพิ่ม A ให้พรรค ID 99 | ระบบปฏิเสธ แจ้งว่าไม่พบพรรค |
| TC-08 | ไม่มีผู้ใช้ ID 99 ในระบบ | admin เพิ่มผู้ใช้ ID 99 เป็นผู้สมัคร | ระบบปฏิเสธ แจ้งว่าไม่พบผู้ใช้ |
| TC-09 | ข้อมูลอื่นถูกต้องครบ | admin เพิ่มผู้สมัครโดยไม่ส่ง `partyId` (หรือช่องจำเป็นอื่น) | ระบบปฏิเสธ แจ้งให้กรอกข้อมูลที่จำเป็นให้ครบ |
| TC-10 | ข้อมูลอื่นถูกต้องครบ | admin เพิ่มผู้สมัครด้วยหมายเลข `0`, `-1` หรือ `1.5` | ระบบควรปฏิเสธ เพราะหมายเลขผู้สมัครต้องเป็นจำนวนเต็มบวก (ค่าขอบ — ต้องลองว่าโค้ดเดิมทำได้จริงไหม) |

**หมายเหตุ:** TC-01, TC-02, TC-06 เป็นกรณีที่ควรสำเร็จ (happy path) · TC-03 ถึง TC-09 เป็นกรณีที่ควรล้มเหลว · TC-10 เป็นการทดสอบค่าขอบ (boundary value)
